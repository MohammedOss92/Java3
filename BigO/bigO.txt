### أولًا: ما الفرق بين Time وSpace؟

تخيّل أنك ترتب 100 رقم.

هناك سؤالان مختلفان:

1\. Time Complexity — التعقيد الزمني

كم عملية يحتاج البرنامج لتنفيذ المهمة؟

مثلًا:

* مقارنة رقم برقم.

* تكرار حلقة.

* البحث عن عنصر.

* تبديل عنصرين.

كلما زاد عدد الأرقام، هل يزداد عدد العمليات؟

2\. Space Complexity — التعقيد المكاني

كم ذاكرة إضافية يحتاج البرنامج أثناء تنفيذ المهمة؟

مثلًا:

* إنشاء مصفوفة ثانية.

* إنشاء متغيرات إضافية.

* إنشاء قائمة جديدة.

لا نقصد حجم المصفوفة الأصلية الموجودة مسبقًا، بل الذاكرة الإضافية التي يحتاجها الحل.

### ثانيًا: نفهم الرموز

| الرمز    | معناه ببساطة                                   |
| -------- | ---------------------------------------------- |
| O(1)     | عدد العمليات أو مساحة الذاكرة ثابتة            |
| O(log n) | العمل يقلّص حجم البحث إلى النصف تقريبًا كل مرة |
| O(n)     | العمل يزداد مع عدد العناصر                     |
| O(n²)    | العمل يزداد تقريبًا مع مربع عدد العناصر        |

### ثالثًا: لماذا حصلنا على هذه النتائج؟

### 1\. Linear Search

نبحث عنصرًا عنصرًا.

* 10 عناصر: قد نحتاج 10 مقارنات.

* 100 عنصر: قد نحتاج 100 مقارنة.

إذن Time هو `O(n)`.

أما Space فنستخدم متغيرات قليلة مثل `i` و`found`، ولا ننشئ مصفوفة ثانية.

إذن Space هو `O(1)`.

### 2\. Binary Search

نقسم مجال البحث إلى النصف في كل مرة.

* 16 عنصرًا.

* ثم 8.

* ثم 4.

* ثم 2.

* ثم 1.

إذن Time هو `O(log n)`.

ونستخدم `low` و`high` و`mid` فقط، لذلك Space هو `O(1)`.

### 3\. Bubble Sort

نقارن العناصر المتجاورة، ولدينا حلقتان متداخلتان.

كلما زاد عدد العناصر، زادت المقارنات بصورة تربيعية.

إذن Time هو `O(n²)` في أسوأ حالة.

ونرتب المصفوفة الأصلية باستخدام `temp`، لذلك Space هو `O(1)`.

### 4\. Selection Sort

نبحث عن أصغر عنصر في الجزء غير المرتب، ثم نضعه في مكانه.

حتى لو كانت المصفوفة مرتبة مسبقًا، نستمر في البحث.

إذن Time هو `O(n²)`.

ونستخدم `temp` للتبديل دون مصفوفة ثانية، لذلك Space هو `O(1)`.

### المقارنة التي وصلنا إليها

| الخوارزمية     | Time     | Space |
| -------------- | -------- | ----- |
| Linear Search  | O(n)     | O(1)  |
| Binary Search  | O(log n) | O(1)  |
| Bubble Sort    | O(n²)    | O(1)  |
| Selection Sort | O(n²)    | O(1)  |

### رسم يساعدك على فهم Time Complexity

### الآن أريد التأكد أنك فهمت، وليس أنك حفظت

تخيّل أن لدينا مصفوفة فيها 100 عنصر.

كتبنا برنامجًا يستخدم حلقة واحدة تمر على العناصر كلها، ولا ينشئ أي مصفوفة أو قائمة جديدة.

السؤال الأول: ما هو Time Complexity؟ ولماذا؟

_______________________________
Time Complexity حسب ترتيب المصفوفة

الخوارزمية| مرتبة تصاعديًا| مرتبة بالعكس
Linear Search| O(n) أسوأ حالة| O(n) أسوأ حالة
Binary Search| O(log n)| O(log n)
Bubble Sort| O(n) مع شرط التوقف المبكر| O(n²)
Selection Sort| O(n²)| O(n²)
Insertion Sort| O(n)| O(n²)

ملاحظات

- Linear Search: يعتمد على موقع العنصر المطلوب، وليس على ترتيب المصفوفة.
- Binary Search: يحتاج مصفوفة مرتبة، ويمكن البحث تصاعديًا أو تنازليًا إذا عُدّل منطق المقارنة.
- Bubble Sort: يصل إلى O(n) في أفضل حالة إذا استخدمنا متغيرًا مثل "swapped" للتوقف عند عدم حدوث أي تبديل.
- Selection Sort: يستمر في البحث عن أصغر عنصر حتى لو كانت المصفوفة مرتبة.
- Insertion Sort: يكون سريعًا عندما تكون المصفوفة مرتبة مسبقًا، ويكون أبطأ عندما تكون معكوسة.


سؤال ممتاز. خلينا نفهم لماذا `Insertion Sort` تختلف عندما تكون المصفوفة مرتبة أو معكوسة.

### أولًا: عندما تكون المصفوفة مرتبة تصاعديًا

```java
int[] numbers = {1, 2, 3, 4, 5};
```

تذكّر أن Insertion Sort تبدأ من الفهرس `1`، وتأخذ العنصر الحالي وتضعه في مكانه الصحيح بين العناصر السابقة.

* نأخذ `2` ونقارنه مع `1` → لا نحتاج إلى تحريك.

* نأخذ `3` ونقارنه مع `2` → لا نحتاج إلى تحريك.

* نأخذ `4` ونقارنه مع `3` → لا نحتاج إلى تحريك.

* نأخذ `5` ونقارنه مع `4` → لا نحتاج إلى تحريك.

كل عنصر يحتاج إلى مقارنة واحدة فقط.

إذن عدد المقارنات يزداد مع عدد العناصر:

O(n)

### ثانيًا: عندما تكون المصفوفة معكوسة

```java
int[] numbers = {5, 4, 3, 2, 1};
```

نبدأ من الفهرس `1`:

* نأخذ `4` ونقارنه مع `5` → نحرك `5`.

* نأخذ `3` ونقارنه مع `5` ثم `4` → نحرك الاثنين.

* نأخذ `2` ونقارنه مع `5` ثم `4` ثم `3`.

* نأخذ `1` ونقارنه مع جميع العناصر السابقة.

لاحظ كيف يزداد العمل في كل مرة.

| العنصر الحالي | عدد المقارنات |
| ------------- | ------------- |
| 4             | 1             |
| 3             | 2             |
| 2             | 3             |
| 1             | 4             |
| المجموع       | 10            |

لذلك يكون التعقيد:

O(n²)

### الخلاصة

* المصفوفة المرتبة: كل عنصر تقريبًا يحتاج مقارنة واحدة.

* المصفوفة المعكوسة: كل عنصر يحتاج الرجوع عبر العناصر السابقة وتحريكها.

أريد التأكد أنك فهمت الفكرة:

إذا كانت المصفوفة:

```java
{1, 2, 3, 5, 4}
```

عندما نأخذ `4` بوصفه `key`، كم عنصرًا سنحتاج إلى تحريكه إلى اليمين؟
