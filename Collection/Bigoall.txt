وصلني 100 طلب مطعم، ثم 50 طلباً جديداً. الزبائن يعدّلون طلباتهم، يلغونها، يضيفون وجبات، ويطلبون البحث عن طلب بواسطة رقم الطلب ID أو موقعه Index. أي هيكل بيانات أستخدم؟ ولماذا؟

هذا هو التفكير الصحيح في هياكل البيانات.

سنأخذ مشروع إدارة طلبات مطعم، ونبني عليه مقارنة عملية بين Java وKotlin وPython، مع فهم Time Complexity وSpace Complexity.

### 1\. أولاً: ما العمليات التي نحتاجها؟

| العملية          | مثال                      |
| ---------------- | ------------------------- |
| العرض            | عرض جميع الطلبات          |
| البحث بالـ Index | الطلب الموجود في الموقع 5 |
| البحث بالـ ID    | الطلب رقم 1050            |
| الإضافة          | وصول طلب جديد             |
| الحذف بالـ Index | حذف الطلب في الموقع 3     |
| الحذف بالـ ID    | إلغاء الطلب 1050          |
| التعديل          | تغيير وجبة أو سعر أو كمية |
| الترتيب          | ترتيب الطلبات حسب السعر   |
| منع التكرار      | عدم تكرار رقم الطلب       |
| الأولوية         | الطلبات المستعجلة أولاً   |
| FIFO             | أقدم طلب يُعالج أولاً     |

مهم جداً: لا يوجد هيكل واحد هو الأفضل لكل هذه العمليات.

### 2\. مقارنة الهياكل حسب كل عملية

هذه أهم مقارنة يجب أن تفهمها، وليست للحفظ.

Time Complexity – متوسط الأداء، باستثناء الحالات التي نوضحها

| الهيكل        | عرض الكل | بحث Index | بحث ID / Value | إضافة    | حذف         |
| ------------- | -------- | --------- | -------------- | -------- | ----------- |
| ArrayList     | O(n)     | O(1)      | O(n)           | O(1)*    | O(n)        |
| LinkedList    | O(n)     | O(n)      | O(n)           | O(1)**   | O(n)        |
| HashMap       | O(n)     | —         | O(1)           | O(1)     | O(1)        |
| LinkedHashMap | O(n)     | —         | O(1)           | O(1)     | O(1)        |
| TreeMap       | O(n)     | —         | O(log n)       | O(log n) | O(log n)    |
| HashSet       | O(n)     | —         | O(1)           | O(1)     | O(1)        |
| TreeSet       | O(n)     | —         | O(log n)       | O(log n) | O(log n)    |
| ArrayDeque    | O(n)     | —         | O(n)           | O(1)*    | O(1)*       |
| PriorityQueue | O(n)     | —         | O(n)           | O(log n) | O(log n)*** |

* `O(1)*` في ArrayList تعني الإضافة في النهاية بالمتوسط، وليس في أي موقع.

* `O(1)**` في LinkedList تعني الإضافة والحذف عند الطرف أو عندما يكون موقع العقدة معروفاً.

* `O(log n)***` في PriorityQueue تعني حذف العنصر ذي الأولوية، وليس حذف أي عنصر تختاره.

### 5\. خطتنا التعليمية

لن ندرس كل شيء دفعة واحدة. سنبني مشروعاً تدريجياً:

* المرحلة الأولى: ArrayList

    إضافة، عرض، بحث بالـ Index، حذف، تعديل.

* المرحلة الثانية: HashMap

    بحث وتعديل وحذف باستخدام ID.

* المرحلة الثالثة: ArrayList + HashMap

    الجمع بين الهيكلين في نظام طلبات واحد.

* المرحلة الرابعة: LinkedList وDeque وQueue

    الطلبات التي تدخل وتخرج، ومعالجة الطوابير.

* المرحلة الخامسة: HashSet وTreeSet وTreeMap

    منع التكرار والترتيب.

* المرحلة السادسة: PriorityQueue

    الطلبات المستعجلة والأولويات.

* المرحلة السابعة: مشروع متكامل

    إدارة طلبات الزبائن وتعديلها وإلغاؤها والبحث عنها.
